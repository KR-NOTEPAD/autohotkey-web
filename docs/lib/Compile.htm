컴파일 / EXE 암호화

컴파일 방법

stock Ahk2Exe로는 컴파일할 수 없습니다(새 명령을 모르고, 스크립트 리소스 이름과 베이스가 다릅니다). 전용 컴파일러 AhkWeb2Exe를 쓰세요.

  • 컴파일러 창: 시작 메뉴 AhkWeb2Exe 컴파일러, 또는 AhkWeb2Exe.exe를 인자 없이 실행
  • 탐색기: .ahkw 우클릭 → 컴파일 (.exe) / 컴파일 (옵션 창)...
  • SciTE4: .ahkw를 열고 Ctrl+F7
  • 명령줄: AhkWeb2Exe.exe /in myapp.ahkw [/out myapp.exe] [/icon app.ico] [/setup] [/silent]

컴파일러 창

탭내용
기본스크립트(최근 목록), 출력 exe, 아이콘(미리보기), 베이스, 출력 방식(단일 EXE / EXE + 설치 마법사), 컴파일 후 실행, 출력 폴더 열기, 관리자 권한으로 실행
버전 정보파일 설명·버전·제품명·회사·저작권·설명·원본 파일 이름 (탐색기 속성 > 자세히)
파일 포함함께 배포할 파일/폴더(확장자 제한 없음, 드래그&드롭), 대상 경로, 추출 위치·방식
설치 마법사앱 이름·게시자·설치 폴더·설치 범위·사용권 계약·바로가기·설치 후 실행
고급트레이 상태 아이콘(Suspend/Pause), 코드 서명(signtool)

입력한 값은 스크립트마다 기억되어 다음엔 [컴파일]만 누르면 됩니다. 서명 암호는 이 PC에만 DPAPI로 암호화되어 저장됩니다.

#Include · Lib · FileInstall

Ahk2Exe처럼 컴파일 시 #Include/#IncludeAgain(<Lib>, 폴더, *i, %A_ScriptDir%·%A_LineFile% 등)과 Lib 폴더 자동 포함 함수를 한 스크립트로 합칩니다. 이때 AutoHotkeyWeb.exe /iLib로 문법도 검사하므로 오류가 있으면 컴파일이 실패하고 위치가 표시됩니다.

FileInstall, 원본, 대상의 원본 파일도 자동으로 exe에 들어갑니다(원본은 변수 없이 써야 합니다).

;@Ahk2Exe-IgnoreBegin … ;@Ahk2Exe-IgnoreEnd 사이는 컴파일본에서 빠지고, /*@Ahk2Exe-Keep … */ 사이는 컴파일본에서만 실행됩니다.

파일 포함 (단일 EXE)

폴더·파일·문서 등 무엇이든 exe 하나에 넣어 배포합니다. 실행하면 스크립트가 시작되기 전에 풀리고, 위치는 A_AhkWebFiles로 얻습니다(컴파일 전에는 A_ScriptDir).

;@AhkWeb-Include data                 ; 폴더 → data\...
;@AhkWeb-Include manual.pdf, docs\    ; 파일 → docs\manual.pdf
;@AhkWeb-ExtractTo exe                ; temp(기본) | exe | appdata | localappdata | 절대경로
;@AhkWeb-ExtractMode newer            ; newer(기본, 바뀐 파일만) | always | missing
FileRead, cfg, %A_AhkWebFiles%\data\config.ini

temp는 종료 시 자동 삭제됩니다(;@AhkWeb-KeepFiles로 유지). exe에 쓰기 권한이 없으면(Program Files 등) LocalAppData\<exe 이름>로 자동 전환됩니다.

웹 자산 폴더는 기존처럼 ;@AhkWeb-Assets <폴더>(WebGui, A_AhkWebAssets)도 쓸 수 있습니다.

설치 마법사 (Setup.exe)

출력 방식을 EXE + 설치 마법사로 고르거나 ;@AhkWeb-Setup(명령줄 /setup)을 쓰면, exe와 포함 파일을 묶은 <앱 이름>_Setup.exe를 함께 만듭니다. Inno Setup 같은 외부 도구가 필요 없습니다.

  • 마법사: 환영 → 사용권 계약(지정 시) → 설치 폴더·바로가기 → 설치 → 완료(바로 실행)
  • 제거 프로그램 생성, 앱 및 기능(프로그램 추가/제거) 등록, 같은 앱은 기존 폴더에 업그레이드
  • 설치 범위: 현재 사용자(%LocalAppData%\Programs, 관리자 불필요) 또는 모든 사용자(Program Files, UAC)
  • 무인 설치: Setup.exe /S /D=C:\경로, 무인 제거: uninstall.exe /S
  • Setup.exe 아이콘·버전 정보는 앱 아이콘·버전 정보를 따릅니다.
;@AhkWeb-Setup
;@AhkWeb-SetupName 내 프로그램
;@AhkWeb-SetupPublisher 내 회사
;@AhkWeb-SetupScope user              ; user | machine
;@AhkWeb-SetupLicense LICENSE.txt
;@AhkWeb-SetupShortcuts desktop,startmenu   ; none 이면 만들지 않음
;@AhkWeb-SetupRun 1
;@AhkWeb-SetupOut dist\MyApp_Setup.exe

지시어 요약

;@Ahk2Exe- 또는 ;@AhkWeb-로 시작하며, 컴파일러 창·명령줄 값보다 우선합니다.

SetVersion, SetDescription, SetCopyright, SetCompanyName, SetProductName, SetOrigFilename, SetInternalName, SetName, Set 속성, 값버전 정보
ExeName 경로출력 exe 경로 (%A_ScriptDir% 사용 가능)

EXE 스크립트 암호화 (기본 적용)

컴파일하면 스크립트가 자동으로 난독화·압축되어 exe에 들어갑니다. 비밀번호나 추가 옵션은 없습니다.

  • 리소스 뷰어나 strings로 열어도 스크립트가 평문으로 보이지 않습니다(DEFLATE 압축 + 키스트림 XOR, 컨테이너 AHKW1).
  • 엔진이 실행 시 메모리에서 풀어 읽으므로 동작·속도에는 영향이 없습니다.
  • 서명 스캐너가 스크립트 본문 바이트로 매칭하는 것을 막습니다.
보안 수준: 이것은 난독화입니다. 암호를 받지 않는 자체 실행 exe라 키가 바이너리 안에 있을 수밖에 없고, 실력 있는 리버서는 복원할 수 있습니다. 소스 유출 방지의 1차 방어이지, 강한 비밀 보호가 아닙니다. 진짜 비밀(API 키 등)은 DpapiProtect로 감싸 코드 밖에 두세요.

컴파일된 exe의 파일 속성(버전 정보)은 기본적으로 비어 있습니다 — 제품명·회사명 등 식별 문자열이 들어가지 않습니다. 넣고 싶으면 버전 정보 탭이나 SetVersion 등 지시어로 지정하세요.

중립 식별자 (안티치트 오탐 완화)

오토핫키 자체를 불법 프로그램으로 오인하는 일부 안티치트를 피하려고, 탐지에 쓰이는 지점(창 클래스·창 제목·후킹 뮤텍스·버전 정보)에서 "AutoHotkey" 문자열을 없앴습니다. 내부 리소스 문자열 일부(도움말 파일명, 자체 레지스트리 키 SOFTWARE\AutoHotkeyWeb, WebView2 데이터 폴더명 등)에는 여전히 "AutoHotkey"가 남지만, 이들은 창/뮤텍스/네트워크로 노출되지 않아 지문 탐지와 무관합니다.

항목값
메인 창 클래스AhkwShell (기존 AutoHotkey)
GUI 창 클래스AhkwShellGui
WebGui 창 클래스AhkwWebView
후킹 뮤텍스AhkwShell Kbd / AhkwShell Ptr
창 제목 / 트레이Ahkw Shell
다운로드 User-AgentMozilla/5.0
컴파일된 exe 버전 정보기본 공백 (직접 지정한 값만 들어감)
이 때문에 ahk_class로 창을 찾을 때는 새 클래스 이름을 쓰세요: 예) WinActivate, ahk_class AhkwShell. #SingleInstance와 ahk_class는 그대로 동작합니다.
개발·디버깅은 영향 없음: 인터프리터 AutoHotkeyWeb.exe는 SciTE4 디버거 연동을 위해 제품명과 DBGp appid에 "AutoHotkey"를 유지합니다(네트워크로 나가거나 창 제목에 쓰이지 않음). F5 실행·F7 디버그·컴파일이 모두 그대로 됩니다. 중립화는 배포되는 컴파일 exe에 적용됩니다.
